# 做法與規劃

這份文件寫的是**打算怎麼做**。標「建議」的地方是還沒經過製作人確認的提案，確認後要搬進 DECISIONS.md。

## 一、開發階段
每個階段做完都停下來等製作人確認。

| 階段 | 內容 |
|---|---|
| 一 | 角色企劃（等製作人提供名字與人物模板）、學院設定 |
| 二 | 世界觀、校規設定、故事大綱、章節 |
| 三 | 學校地圖：有哪些區域、各區的玩法（場景探索／異常走廊／規則怪談） |
| 四 | 謎題規劃：每題寫明機制、人數、需要的裝置、單人怎麼解、手機或電腦的替代操作 |
| 五 | 系統雛形：一間樣品教室＋一位樣品角色，驗證第一人稱、多人、手機道具、美術風格 |
| 六 | 序章＋第一章內容 |
| 七 | 測試；之後再擴充後面的章節 |

**建議**：階段五的「技術雛形」（第一人稱移動、手機橫直向、手機掃 QR code 加入當道具）跟劇情無關，可以讓另一個帳號在階段一～四進行的同時先做，最後再套上正式內容。

## 二、遊戲結構

### 主體：第一人稱探索
- 用 Three.js 做 3D 學校。電腦用鍵盤＋滑鼠，手機用左半邊虛擬搖桿移動、右半邊滑動轉視角、點東西調查。
- 場景探索：走進教室、宿舍、圖書館、塔樓，在場景裡找線索、拿道具、組合道具。
- 找異常：一段會反覆出現的固定區域（**建議**：「肖像畫長廊」或「會變的樓梯間」），發現有東西不一樣就回頭，沒有就往前。每一章出現一次、越來越難。
- 規則怪談：入學時拿到《校規》和《宿舍夜間守則》。有些條文是假的或被人竄改過，判斷真假是貫穿整部的主線。因為不做恐怖，違反規則的後果是好笑或麻煩的（例如變成青蛙、被傳送回宿舍、被罰抄校規），不是嚇人或死亡。

### 1～4 人
- 每一題都要能單人解。
- **建議**：單人時帶著一隻**使魔**（貓頭鷹、黑貓…）。切換到使魔的視角就能看另一個房間或監控畫面，原本兩人分工的題目變成一個人切換兩個視角。
- 題目依人數調整：資訊拆成 N 份，人越多，每人拿到的越少、越需要溝通。
- 一定要多人才能玩的題目只放在支線或彩蛋，不放主線。

### 四種多人玩法
- 合作：每人看到不同資訊（**建議**：依角色或學院不同，例如某學院的人看得懂符文、某學院的人看得見隱形墨水）。
- 非對稱：因為不做俯視角，「監控室」的人看的是**水晶球**（另一個房間的畫面）或**活點地圖式的魔法地圖**（插畫風的平面圖，上面有隊友的位置點），用來引導房間裡的人。這只是一個畫面，不是俯視角玩法。
- 接力：每人解一段，把成果（一個字、一個道具）交給下一位。
- 跨裝置：見下一節。

### 跨裝置（手機當道具）
- 電腦主畫面顯示 QR code，手機掃了就以「道具」身分加入同一個房間。
- 拿手機當道具時強制直向；一般遊玩時強制橫向。
  - Android 可以在全螢幕時鎖定方向。iPhone 不能鎖，只能在方向不對時蓋一層「請轉成橫向／直向」的提示。
- **建議**：手機最主要的道具是**魔杖**——揮動、指向、畫符號來施咒（陀螺儀）。另外可以當手電筒（光照咒）、羅盤、鑰匙、放大鏡。
- 感測器都要先請玩家授權（iPhone 的陀螺儀要點按鈕才能啟用；麥克風、相機要 HTTPS，workers.dev 本來就是）。玩家拒絕授權或沒有手機時，每一題都要有替代操作（例如吹氣→長按、搖晃→拖曳）。

### 定位、真實時間、後設題
- 定位：玩家不一定在同一個城市，**不放主線**，做成選玩的隱藏內容；主線改用遊戲內的魔法羅盤。
- 真實時間：**建議**做「宵禁後」的夜間學校（真實時間晚上某個時段，學校會變得不一樣），不能卡住主線。
- 後設題（原始碼、Console、標籤頁標題、縮放網頁）：手機上幾乎做不到，只出給電腦主畫面的玩家，或手機版另外給替代線索。build 混淆 JS 時，後設題需要的線索文字要刻意保留下來。

## 四、技術
- 第一人稱：Three.js。
- 登入、存檔、遊玩紀錄、回報問題：照千山夜錄的 `src/game/platform.mjs` 做法，接夜語工作室大廳（同一個 Supabase 專案）。遊戲的 slug、資料表與函式前綴還沒定（**建議**：slug `milner`，前綴 `ml_`）。
- 多人：照千山夜錄的做法（Supabase 房間＋即時同步，答案由伺服器的 Edge Function 判斷，網頁裡不放答案）。
  - 隊友的位置只同步「在哪個房間、面向哪裡」，不同步每一步，比較穩定。
- 單人：同一套程式、同一個伺服器判斷答案，只是房間只有一個人。
- 發佈：Cloudflare Workers，只發佈 build 產生的檔案（原始碼、文件、伺服器程式不發佈）。
- **建議**：謎題、劇情、場景物件都寫成資料檔，引擎讀資料來產生，兩個帳號可以一個寫內容、一個寫引擎，不會改到同一個檔案。

## 五、美術
製作人的要求：不要像千山夜錄那樣，圖只是貼上去的感覺。

- 場景：用 Three.js 做真正的 3D 空間（石牆、燭台、書架、彩繪玻璃、會飄的書），光影、霧、灰塵粒子即時計算。場景本身就是遊戲世界，不是背景圖。
- 角色，兩個選擇：
  1. 全部用程式做：風格化的 3D 角色或 2D 向量立繪，會眨眼、有表情、會呼吸和說話，而且會被場景的燭光照到。風格統一、修改快，但偏簡約、卡通化，不會有手繪插畫的精緻度。
  2. 製作人用 AI 繪圖生成立繪（我們提供提示詞），再拆成分層，加上場景光源調色、景深、動態和表情切換，融入場景。
- 先在階段五用方法 1 做樣品，讓製作人決定。

## 六、其他建議（待製作人確認）
- **調性**：懸疑冒險為主，帶溫馨和一點幽默。主線謎團可以是「校規被人偷偷改寫了，是誰、為什麼」，剛好接上規則怪談。
- **分學院當教學關**：開場用分學院儀式（一段性格問答），同時教玩家操作。分到的學院決定能力（看得到的資訊不同），正好用在合作題。
- **章節＝一個學年**：開學、期中、節慶（例如萬聖節或冬至舞會）、期末考。每一章的謎題對應課程：魔藥課（顏色混合）、天文課（星座）、符文課（密碼）、占卜課（真假推理）、魔咒課（麥克風念咒）、飛行課（陀螺儀）。
- **可以重玩**：每個房間的部分密碼由伺服器隨機產生，同一題每次答案不同。
- **可列印的實體道具**：入學通知書、校規 PDF，印出來可以用手機相機掃描，算是加分玩法，不印也能玩。
