# 階段五：遊戲系統規劃（草稿，等製作人確認）

技術雛形（`prototype/`）證明了第一人稱、手機橫直向、魔杖、寫實角色都做得到。這份文件規劃怎麼把它做成**完整、可以多人玩的第一章**。

## 0. 目標
做完這個階段，玩家可以：
1. 從夜語工作室大廳進入，看到 18+ 提示，選擇語言。
2. 單人開始，或建立、加入 1～4 人的房間（四個字的房號）。
3. 經過分學院儀式、選角色，從序幕玩到第一章結束。
4. 中途離開，下次從最近的段落繼續。

## 1. 整體架構
| 部分 | 放在哪裡 | 說明 |
|---|---|---|
| 遊戲畫面 | `game/` | 由 `prototype/` 整理而來：場景、角色、操作、魔杖、介面 |
| 遊戲資料 | `data/` | 劇情、對話、謎題（**含答案，不發佈**）、地圖物件 |
| 伺服器 | `supabase/` | 資料表與函式（前綴 `ml_`），以及判斷答案的 Edge Function `milner-play` |
| 發佈版 | `dist/` | build 產生：拿掉答案、混淆程式，放到 Cloudflare Workers（`milner`） |
| 工具與測試 | `tools/` | build、資料檢查、自動測試 |

做法以千山夜錄為範本：登入、房間、作答都由伺服器判斷，網頁裡沒有答案。

## 2. 哪些事由誰決定
| 事情 | 由誰決定 | 原因 |
|---|---|---|
| 謎題對錯、提示、進度、章節、誰被抓走、倒數 | **伺服器** | 不能被改，所有人看到的要一樣 |
| 自己的移動、視角 | **自己的裝置** | 要即時、不能卡 |
| 守夜人的行動 | **房主的裝置**計算，再廣播給其他人 | 伺服器沒辦法每秒算 60 次；房主斷線時自動換人接手 |
| 隨機答案（P21、救援題等） | **伺服器**在開房時決定 | 每個房間不同，重玩也不同 |

隊友的位置：每人每秒送 2～4 次「在哪個房間、座標、面向」，只在有移動時送。

## 3. 單人模式
- 走同一套伺服器流程，就是「只有一個人的房間」，所以答案一樣不會出現在網頁裡。
- 另外三位角色由電腦控制，跟在玩家身邊，會在劇情中說話。
- 原本要多人分工的題目，改用使魔視角，做法已寫在 `05-puzzles-ch1.md`。
- 第四幕可以原地復活 3 次。

## 4. 作答與提示
- 每題三張提示便條，由淺到深。用了提示會記錄下來（之後可以做通關評價）。
- 答錯：短暫冷卻，避免亂猜。冷卻時間依題目設定，例如 P21 天平答錯就重新洗牌。
- 多人時，同一題任何人解開都算全隊解開；只有某學院能做的動作，由伺服器檢查是誰做的。

## 5. 存檔與段落
- 第一章分成：序幕、第一幕、第二幕、第三幕（入口～書架、閱覽室、前廳～井室三小段）、第四幕、尾聲。
- 每段開頭是存檔點。離開後再進來，從最近的存檔點繼續；多人時以房間的進度為準。
- 時間到、全員被抓、單人復活用完：從**這一段的開頭**重來。
- 雲端存檔（`game_saves`）記錄：通關過的章節、看過的結局、收集的莉安娜筆記、西里爾的抉擇、設定。

## 6. 語言
- 介面語言每個人自己選，預設中文。
- 謎題語言**一個房間只有一種**，由房主開房時選。因為像 P14 這種題目，中文版和英文版的答案不一樣。
- 劇情對話、字幕跟著各自的介面語言。

## 7. 隊友之間怎麼溝通
多人玩法很依賴溝通，所以要先決定：
- **(a) 內建文字聊天＋快捷標記**（例如「這裡！」「危險」「我需要幫忙」，標記會出現在畫面上）。玩家要講話，就用自己的 Discord 或 LINE 通話。**建議用這個。**
- **(b) 另外再做內建語音通話**：方便，但要多架一台轉接伺服器（有費用），手機上也比較不穩定。

## 8. 畫面流程
大廳 → 18+ 提示 → 語言 → 單人／建立房間／加入房間 → 等待室（房號、隊友名單）→ 序幕：分學院儀式 → 選角色（預設是分到的學院）→ 全員準備 → 遊戲 → 第一章結束畫面（統計、收集進度）

## 9. 分批製作
每一批做完都放上測試網址，請你試玩確認。

| 批次 | 內容 |
|---|---|
| 1 | 架構：`game/` 整理、大廳登入、房間、隊友同步、伺服器作答、build 與發佈 |
| 2 | 序幕＋第一幕（碼頭、主樓、四座宿舍、星盤廳）、P01～P08 |
| 3 | 第二幕：異常長廊（P09、P10） |
| 4 | 第三幕：沉眠圖書館（P11～P25） |
| 5 | 第四幕：守夜人、追逐、躲藏、蝕巢、救援與自救、倒數（P26～P29、R、S） |
| 6 | 尾聲、存檔、英文版、全章測試 |

## 10. 兩個帳號的分工（建議）
| 帳號 | 負責 | 主要資料夾 |
|---|---|---|
| 這個帳號 | 伺服器、房間與同步、作答、劇情系統、謎題資料、build 與發佈、測試 | `supabase/`、`data/`、`tools/`、`game/src/net/`、`game/src/logic/` |
| 另一個帳號 | 角色模型與動畫、場景美術（3D 房間）、守夜人的外型與蝕化演出、魔杖 | `game/src/art/`、`game/models/`、`prototype/` |

兩邊要共用的地方（例如場景裡謎題物件的位置），由這個帳號先定好資料格式，美術照格式擺放。

## 11. 限制與風險
- **Supabase 免費方案的額度**：即時訊息每月約 200 萬則、同時連線約 200 個。隊友位置每秒送 2～4 次，4 人房間每小時大約 3～6 萬則，所以免費方案大約只夠**幾十個「房間小時」**。
  - 對策：只在移動時送、降低頻率、靜止時不送。
  - 玩家變多時要升級付費方案，Pro 方案每月約 25 美元。
- **共用的 Supabase 專案**：這是大廳和其他遊戲正在用的正式環境。建立 `ml_` 資料表、部署函式之前，我會先跟你確認，不會動到其他遊戲。
- **寫實模型的檔案大小**：每個角色要壓到 5MB 以下，手機才載得動；第一次進遊戲會有載入畫面。
- **iPhone 不能鎖定方向**：只能用提示請玩家轉手機。

## 12. 要問製作人的
1. 架構和分批的做法可以嗎？
2. 隊友溝通用 **(a) 文字聊天＋快捷標記，語音用 Discord／LINE**，還是 **(b) 內建語音**？
3. 謎題語言「一個房間一種，由房主選」可以嗎？
4. 兩個帳號照第 10 節分工可以嗎？可以的話，請另一個帳號照這個分工繼續。
5. Supabase 免費額度只夠幾十個房間小時，可以先用免費方案測試，玩家變多再升級嗎？
